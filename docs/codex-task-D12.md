## 0. 왜 이걸 하는가 — 측정된 문제다

도현: **"화살을 계속 쏘니 재미가 없고, 계속 도망가면 피하기만 한다. 다른 목적이 필요할 듯"**

`tools/balance-probe.mjs` 가 이걸 수치로 증명한다:

| 전략 | 결과 |
|---|---|
| **D 홀드 (계속 도망)** | 60초 **무피해** 1696점 |
| 무입력 | 38.7초 사망 |

**최적 전략이 "D 누르고 아무것도 안 하기"다.** 쏘면 조준 때문에 250→137 로 느려져
호랑이가 붙으니 **쏠 이유가 없다.** 위험에 대가가 없어서 회피만 남는다.
게다가 점수의 대부분이 **거리 점수**라 도망이 곧 벌이다.

## 1. 틀 — 도현 결정

**사냥 경술대회(강무) 도중에 진짜 호랑이가 난입한다.**

이 한 줄이 여러 개를 동시에 푼다:
- 코스에 **과녁**이 있는 이유가 설명된다
- 호랑이가 각본 속 적이 아니라 **침입자**가 된다
- **온보딩이 공짜로 생긴다** — 대회는 평화롭게 시작하므로 처음 몇 초는
  안전하게 조준을 배운다. 지금은 시작하자마자 추격이라 배울 틈이 없다

### 진행
1. **시작 ~ `tigerEnterX`**: 과녁만 흐른다. 호랑이 없음. 조준·발사를 익히는 구간
2. **`tigerEnterX` 도달**: 호랑이 난입. 화면에 짧은 경고(주홍). 이후 기존 교전 전부 유효
3. 이후 과녁은 계속 나온다 — 대회는 계속되고 있고, 플레이어는 그 와중에 쫓긴다

`tigerEnterX` 는 **월드 거리 기준**(시간 아님)으로 `CFG` 에 둔다. 2000~3000 사이에서 시작하라.
⚠ 호랑이가 없는 동안 `S.tiger` 를 `null` 로 만들지 마라 — 다른 코드가 전부 깨진다.
`S.tiger.state` 에 **`offstage`** 같은 상태를 추가하고 그 동안 업데이트/렌더를 건너뛰는 편이 안전하다.

## 2. 과녁

**새 파일 `src/target.js`** (sim). `obstacle.js` 의 스폰 구조를 그대로 본떠라 — 검증된 패턴이다.

- 배치는 **seeded PRNG 만**. `Math.random()` 금지. `obstacle.js` 가 하는 그대로
- 높이 2~3단(높은 과녁·중간·낮은 과녁) — **매번 조준 각이 달라야 한다.**
  "화살을 계속 쏘니 재미없다"의 절반은 조준이 늘 같아서다
- 화살 명중 판정은 `arrow.js` 에 추가한다. 호랑이 판정과 같은 방식(축 정렬 상자)
- 지나치면 사라진다. 놓친 것에 벌은 주지 마라 — 안 쏘는 선택 자체가 이미 점수 손실이다
- **연속 명중(콤보)** 배수를 둬라. 빗맞거나 지나치면 초기화.
  이게 "한 발만 더" 를 만든다

### 명중 보상 — 이게 설계의 핵심 고리다
과녁을 맞히면 **짧은 질주**(0.5~0.8초 속도 증가)를 준다.

```
조준한다 → 250에서 137로 느려진다 → 호랑이가 붙는다
맞힌다   → 짧게 질주 → 거리를 되찾는다      = 순이득
빗맞는다 → 느려진 값만 남는다               = 순손실
```

**실력이 곧 거리가 된다.** `HANDOFF.md` 의 "명중이 거리를 회복시킨다"가 과녁에도 적용되는 것이다.
질주 값은 `CFG` 에 두고, **호랑이 `chaseSpeed`(245)보다 확실히 빨라야** 의미가 있다.

## 3. 점수를 다시 짠다 — 이게 없으면 위 전부가 헛수고다

지금 `CFG.score`: `distancePx: 10`(10px 당 1점) · `hit: 25` · `strongHit: 60` · `kill: 500`.
거리가 주 수입원이라 **도망이 최적**이다.

- **거리 점수를 크게 낮춰라** (지금의 1/3 수준에서 시작)
- **과녁 명중을 주 수입원으로.** 콤보 배수까지 붙으면 잘 쏘는 쪽이 압도적으로 높아야 한다
- 호랑이 처치(500)와 명중 점수는 유지하되, 과녁과의 균형을 보고 조정하라

### 합격 기준 (probe 로 판정한다)
**`D 홀드`(도망만) 점수가 과녁을 노리는 플레이보다 확실히 낮아야 한다.**
`tools/balance-probe.mjs` 에 **과녁을 노리는 입력 패턴**을 추가하라
(예: 과녁이 사거리에 들어오면 조준·발사하는 간단한 봇). 두 점수를 나란히 찍어라.
**도망 점수가 더 높으면 이 작업은 실패다.**

## 4. 화면

- **과녁 스프라이트**를 `config.js` 문자열 그리드로 (기존 방식). 먹 + 주홍 과녁면.
  ⚠ **주홍은 위험 전용**이라는 규율이 있었다. 과녁의 홍심에 주홍을 쓰면 예고와 헷갈린다 —
  과녁은 **먹 + 한지**로 그리고, 명중 순간에만 짧게 주홍을 쓰는 편이 안전하다.
  판단해서 캡처로 확인하라
- 명중 시 짧은 피드백(먼지·번쩍·점수 팝업). 콤보 배수를 HUD 에
- **호랑이 난입 순간**: 짧고 확실한 연출. 화면 흔들림 + 주홍 경고 문구 1~2초
- 타이틀 부제를 틀에 맞춰라 (지금 "활 하나로 호랑이를 따돌려라").
  예: **"강무 중, 진짜 호랑이가 나타났다"** — 문구는 네가 다듬어라
- 조작법 상시 표시는 **계속 유지**(대회 필수 요건)

## 5. 결정론 — 이번엔 sim 을 바꾸므로 특히 중요하다

- `target.js`·`arrow.js`·`config.js`·`state.js`·`sim.js` 는 **전부 스캔 대상**이다.
  `Math.sin/cos/pow/atan2/hypot`·`**`·`Math.random`·`Date.now`·`document`·`window` 금지
- 배치 난수는 `rng.js` 의 순수 함수형 PRNG 만
- 새 상태는 전부 `state.js` 의 `createState` 에 넣어라. 모듈 지역 상태 금지
- **리플레이 왕복이 깨지지 않는지** 반드시 확인하라 (테스트 2번이 잡는다)
