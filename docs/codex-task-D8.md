## 0. 도현의 판정

- **"다리 부분이 너무 짜친다"**
- **"그래픽을 공룡게임 비슷하게 만들면 좋을듯"**
- 범위 판정: **민화 4색은 유지하고, 공룡게임의 문법을 가져온다**

다리 문제는 **해부학으로 풀지 않는다.** 공룡게임의 다리는 2프레임 교대가 전부다.
양식을 바꾸면 문제 자체가 사라진다. 이전 D6 지시서에 있던 2본 IK 리깅 계획은 **폐기됐다.**

## 1. 왜 이 둘이 충돌하지 않는가 (구현 전에 읽어라)

공룡게임은 **흰 바탕에 검은 실루엣**이고, 민화는 **한지에 먹**이다. 같은 것을 가리킨다.
현재 배경이 어두운색(`C.bg #12101a`)인데 **이걸 뒤집는 것이 이번 작업의 골자**다.

### 4색에 직업을 하나씩만 준다 — 이 규율을 깨지 마라

| 색 | 유일한 용도 |
|---|---|
| 한지 `C.paper #E8DCC0` | 배경(하늘·지면) |
| 먹 `C.ink #2B2320` | 사슴+기수 · 장애물 · 지면선 · UI 글자 · 그림자 |
| 황토 `C.ochre #C8862A` | **호랑이 전용** (민화 까치호랑이가 황토 바탕에 먹 줄무늬다) |
| 주홍 `C.vermilion #B03A2E` | **예고·위험 전용** — 텔레그래프, 피격 플래시, 하트 소진 |

주홍을 위험에만 묶어두면 한지 바탕에서 빨간 예고가 최대로 튄다.
**0.5초 안에 자세를 바꿔야 하는 게임이라 이게 가장 중요한 가독성이다.**
남은 `C` 항목(`sky`·`ground`·`player`·`tiger`·`obs`·`hud` 등)은 위 넷을 가리키게 정리하거나 지워라.

깊이 표현이 필요하면 **먹의 알파 두 단계만** 허용한다 (`C.inkFar` 0.14 · `C.inkMid` 0.26 같은 이름을
`config.js` 에 두고 그 둘만 쓴다). 세 번째 회색을 만들지 마라.

## 2. 스프라이트를 `config.js` 의 문자열로 둔다

공룡게임이 실제로 이 구조다. 나중에 진짜 픽셀아트로 갈아끼울 때 **렌더 코드를 안 건드려도 되고**,
도현이 한 칸씩 직접 고칠 수 있다.

```js
art: {
  px: 3,                    // 아트 픽셀 1 = 뷰 단위 3 → 320×180 격자
  sprites: {
    deerRunA: [
      '.....XX.......',
      '....XXXX......',
      // '.' = 투명 · 'X' = 주색 · 'o' = 보조색
    ],
    // ...
  }
}
```

- 모든 행의 길이가 같아야 한다. 스프라이트마다 행 길이가 일정한지 렌더 시작 시 한 번 검증하고,
  틀리면 콘솔에 이름을 찍어라 (조용히 깨지면 못 찾는다)
- `render.js` 에 `blit(ctx, sprite, x, y, { color, alt, flip, px })` 하나를 만든다.
  `flip` 이면 좌우 반전(호랑이가 뒤돌 때). **좌표는 반드시 `px` 격자에 스냅**한다 —
  `Math.round(v / px) * px`. 스냅을 빼면 가장자리가 흐려져 이 양식이 통째로 죽는다
- 같은 색 칸이 가로로 이어지면 **한 번의 `fillRect` 로 묶어라** (런 렝스). 칸마다 fillRect 하면
  1프레임에 수천 번 호출된다

### 필요한 스프라이트

**사슴+기수 (주색 = 먹)** — 기수는 스프라이트에 함께 그린다. 하나의 실루엣으로 읽혀야 한다
- `deerRunA` · `deerRunB` — 달리기 2프레임 (다리 위치만 다르면 된다)
- `deerCrouch` — 수그린 자세 (`crouchH 52` 에 맞게 낮다)
- `deerJump` — 공중, 다리를 접은 자세

**호랑이 (주색 = 황토, 보조색 `o` = 먹 줄무늬)**
- `tigerRunA` · `tigerRunB` — 달리기 2프레임
- `tigerBrace` — 뒤도는 중 (몸이 좁아 보이게)
- `tigerWindup` — 앞발을 뒤로 젖힌 자세. **가장 크고 위협적으로**
- `tigerSwing` — 앞발을 뻗은 자세

**장애물 (먹)** — `rockLow` · `rockHigh` · `branch`

크기 기준(뷰 단위 → `px 3` 기준 아트 픽셀):
사슴 `w 70 × h 96` → 약 **23×32** · 호랑이 `w 120 × h 74` → 약 **40×25**.
`CFG.view`/`CFG.player`/`CFG.tiger` 의 판정 크기와 그림이 어긋나면 안 된다 —
**그려진 몸이 판정보다 크면 "안 맞았는데 맞았다"로 읽힌다.** 판정 상자에 맞춰라.

### 애니메이션은 2프레임 교대, 거리 기반
`Math.floor(S.worldX / CFG.art.stridePx) % 2` 로 A/B 를 고른다. 시간 기반으로 하지 마라 —
속도가 변하면 발이 미끄러진다. 호랑이는 `S.tiger.x` 를 쓴다.
**보간하지 마라. 중간 자세는 없다.** 그게 이 양식이다.

## 3. 배경·지면

- 하늘·바닥 = 한지 단색. 그라데이션 금지
- **지면선**: 먹 실선 하나(`px` 두께 1~2칸) + 그 아래로 스크롤하는 성긴 점/짧은 대시.
  공룡게임의 자갈 텍스처가 이것이다. 속도감은 전부 여기서 나온다
- **원경**: 먹 알파 2단계로 산/언덕 실루엣 2층. 곡선 말고 **계단형 rect** 로. 느리게 스크롤
- 구름 몇 개(먹 저알파 rect 덩어리)를 아주 느리게. 있으면 좋고 없어도 된다
- **스피드라인(`drawSpeedLines`)은 지워라** — 이 양식에 안 맞는다. 속도감은 지면 텍스처가 낸다

## 4. 그 밖의 요소

- **텔레그래프**: 주홍 **꽉 찬 사각 띠**(상단/하단). 지금보다 크고 단순하게. 깜빡임은 2프레임 단위로
  (부드러운 페이드 금지)
- **피격 플래시**: 해당 스프라이트를 주홍 단색으로 2프레임 채운다
- **그림자**: 발밑에 먹 저알파 **납작한 rect**(타원 아님). 점프 높이에 따라 좁아지고 옅어진다 —
  **점프 높이를 읽는 유일한 단서다**
- **먼지**: 착지·달리기 때 작은 먹 정사각형 2~3개. 난수 대신 `worldX` 에서 유도해 프레임마다 튀지 않게
- **화살**: 격자 정렬된 작은 먹 rect. `drawAimPreview` 의 궤적은 먹 점 몇 개
- **예외 — 활대와 조준 궤적은 격자에 안 맞아도 된다.** 조준은 연속값이라 양자화하면
  그려진 방향과 실제 발사 방향이 어긋나 조준이 거짓말이 된다. 이 둘만 예외다
- **화면 흔들림(`shakeOf`)은 유지하되 `px` 격자로 스냅**해서 흔들어라. 안 그러면 화면 전체가 흐려진다

## 5. UI — 요건을 깨지 마라

- **조작법 표는 타이틀에 상시 표시** (대회 필수 요건). 터치 모드 분기(D5)도 그대로 유지
- **터치 패드(`drawTouchPads`)는 계속 그려야 한다.** 새 팔레트에 맞춰 색만 바꿔라
  (한지 저알파 채움 + 먹 테두리, 눌림은 황토)
- HUD 하트·점수·차지 게이지: 먹으로. 하트가 빈 칸은 테두리만, 피격 순간은 주홍
- 타이틀/게임오버 오버레이: 한지 패널 + 먹 글자 + 주홍 강조 한 곳. 지금 구조는 유지하고 색만 갈아라
- 글꼴은 `system-ui` 그대로 쓰되 **볼드 + 자간 넓게**. 픽셀 글꼴을 새로 만들지 마라 (시간이 없다)

## 7. 지울 것

`config.js` 의 **`rig` 블록 전체를 지워라.** 중단된 2본 IK 리깅 런의 잔재이고 아무도 안 읽는다.
그림자·먼지 값이 필요하면 `art` 안에 새로 이름 붙여 넣어라.
