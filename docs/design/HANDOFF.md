# 호랑이 추격 — Claude Code 인수인계

## 이 프로젝트가 뭔지
**강무(講武) — 사냥 경술대회 도중에 진짜 호랑이가 난입한다.**
사슴 위에서 과녁을 맞히며 달리는 기마궁술 시합인데, 호랑이가 끼어들어 목숨을 건 추격이 된다.
2D 사이드뷰. 크롬 공룡게임 구조를 베이스로, **거리를 플레이어가 직접 조절한다**는 점이 다르다.

이 틀은 세 가지를 동시에 푼다 (도현 결정, 2026-08-21):
- 코스에 **과녁이 있는 이유**가 설명된다
- 호랑이가 각본 속 적이 아니라 **침입자**가 된다
- **온보딩이 공짜로 생긴다** — 대회는 평화롭게 시작하므로(`CFG.tiger.enterX` 전까지 과녁만
  흐른다) 처음 구간에서 안전하게 조준을 배운다

## 코어 루프 (이걸 깨는 변경은 하지 말 것)
1. 사슴은 계속 달린다. `D`로 가속, `A`로 감속 → **감속이 곧 호랑이에게 붙는 행위**
2. 거리가 `engageGap` 아래로 떨어지면 호랑이가 추격을 멈추고 앞발을 든다
3. 후려치기 0.5초 전, 노리는 높이가 **빨간 칸**으로 표시된다
   - 서 있으면 상단을 노린다 → `S`로 수그려 피한다
   - 수그려 있으면 하단을 노린다 → `W`로 뛰어 피한다
   - 즉 **호랑이는 항상 지금 자세를 거울처럼 노린다.** 가만히 있으면 100% 맞는다
4. 휘두른 직후 `recover` 구간에만 피해 배율 2배가 붙는다 → 붙어야만 딜이 나온다
5. 조준 중에는 속도가 절반 이하로 떨어진다 → 강한 화살을 원할수록 거리를 내준다

6. **과녁을 맞히면 짧게 질주한다** (`CFG.target.dashSpeed`) → 조준으로 잃은 거리를 되찾는다.
   빗맞으면 느려진 값만 남아 순손실. **실력이 곧 거리다.**
7. 연속 명중 콤보가 점수 배수를 올린다. 빗맞거나 지나치면 초기화

**이 게임의 유일한 자원은 거리다.** 장애물 충돌·조준·후퇴가 전부 거리 손실로 수렴하고,
명중은 거리 회복으로 돌아온다. 체력바를 추가하거나 다른 자원을 늘리는 방향은 피할 것.

### 왜 점수를 거리에서 과녁으로 옮겼는가 (2026-08-21)
거리 점수가 주 수입원이던 시절, `tools/balance-probe.mjs` 가 이걸 잡아냈다:
**최적 전략이 "D 누르고 아무것도 안 하기"였다** (60초 무피해 1696점).
쏘면 조준 때문에 250→137 로 느려져 호랑이가 붙으니 쏠 이유가 없었다.
거리 점수 간격을 10px→30px 로 깎고 과녁(80점 × 최대 5배 콤보)을 주 수입원으로 옮긴 뒤:

| 전략 | 이전 | 이후 |
|---|---|---|
| D 홀드(도망만) | 60초 무피해 1696점 | **42초 사망 400점** |
| 과녁 조준 | — | **60초 생존 8575점** |

**이 역전을 깨는 밸런스 변경은 하지 말 것.** `balance-probe` 의 "과녁 봇 > D 홀드" 판정이
이걸 지킨다.

## 조작
| 키 | 동작 |
|---|---|
| `W` | 점프 (하단 후려치기 회피 / 바위 넘기) |
| `S` | 수그리기 (상단 후려치기 회피 / 늘어진 가지 통과) |
| `A` / `D` | 뒤로 / 앞으로 — 호랑이와의 거리 조절 |
| 마우스 | 조준 방향 |
| 좌클릭 홀드 → 놓기 | 시위 당기기 → 발사 |
| `Space` | 시작 / 재시작 |

**터치(모바일)** — 좌하단 `[뒤][앞]` 가로 쌍 · 우하단 `[점프]` 위 / `[수그림]` 아래 세로 쌍.
**배치가 곧 의미다.** 나머지 화면 전체가 조준 영역. 가로 모드 전용(세로면 안내 오버레이).

## 파일 구조
```
index.html          모듈 진입 (개발용, 로컬 서버 필요)
build.mjs           node build.mjs → dist/play.html (단일 파일, 배포용)
src/
  config.js         전 튜닝값의 단일 출처 — 숫자는 전부 여기에만
  state.js          상태 객체 생성 / gapOf()
  fx.js             hitstop · 화면 흔들림 · 진동
  viewport.js       캔버스 스케일 / 좌표 변환
  input.js          키보드 · 마우스 수집
  player.js         이동 · 점프 · 수그리기 · 존 노출 판정
  tiger.js          추격 ↔ 교전 상태머신, 텔레그래프, 발톱 판정
  arrow.js          차지-릴리스, 화살 물리, 명중
  obstacle.js       바위(점프) · 가지(수그리기)
  render.js         전부 도형 플레이스홀더 — Day 3에 여기만 교체
  main.js           루프 · 배선
```

## 실행
```bash
python3 -m http.server 8000   # 그리고 localhost:8000
node build.mjs                # 단일 파일 산출 → dist/play.html
```
`index.html`은 ES 모듈이라 `file://`로 열면 안 된다. 빠른 확인은 `dist/play.html`을 쓸 것.

## 지켜야 할 규칙
- **숫자는 `config.js`에만.** 다른 파일에서 상수를 새로 만들지 말 것
- **상태는 `S` 객체 하나에만.** 모듈 안에 지역 상태를 두지 말 것
- `render.js`는 읽기 전용. 여기서 상태를 바꾸지 말 것
- hitstop은 `update`만 멈추고 `render`는 계속 돈다. `main.js`의 분기 순서를 바꾸지 말 것
- 새 기능을 넣기 전에 "이게 거리(gap)에 어떻게 연결되는가"를 먼저 답할 것

## 검증된 사항 (헤드리스 시뮬레이션)
- 호랑이 상태 전이 5종 전부 발생 확인
- 자세 유지 시 3연타 사망 (약 10초), 텔레그래프 반응 시 25초간 무피해
  → **신호가 실제로 판독 가능하다는 뜻.** 이 격차가 줄어들면 튜닝이 잘못된 것
- 이동키로는 재시작되지 않음 (Space/Enter/좌클릭만)

새 코드 경로를 만들면 진입점 로그를 먼저 넣고, 일부러 망가뜨려 테스트가 실제로
실패를 잡는지 확인한 뒤에 GREEN을 믿을 것.

## 다음 작업 (우선순위 순)
1. **회피 난이도 비대칭 해소** — 수그리기는 즉시 발동되는데 점프는 체공 타이밍이 필요해
   하단 후려치기가 상단보다 훨씬 어렵다. `player.airClearY` 또는 `tiger.windup`으로 맞출 것
2. **처치 보상 설계** — 지금은 호랑이를 잡아도 다음 개체가 즉시 나오기만 한다.
   회복이든 짧은 숨돌림이든, 잡을 이유가 필요하다
3. **거리 밸런스** — `player.speedBase`(250) vs `tiger.chaseSpeed`(245). 여유가 5뿐이라
   장애물 하나만 박아도 붙는다. 의도인지 확인 후 조정
4. 교전 중 장애물이 겹칠 때의 처리 (지금은 그대로 흘러간다)
5. Day 3: `render.js`를 스프라이트로 교체. 민화풍 실루엣 방향
6. 모바일 입력 복구 — 지금은 키보드/마우스 전용이다
