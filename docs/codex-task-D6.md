# Codex 작업 지시 — D6: 교전 재설계 (평소=뒤에서 후려치기 / 후퇴=추월·차단)

**먼저 `AGENTS.md` 를 읽어라.** 매 단계 `node --test tests/determinism.test.mjs` 유지.

> ⚠ 이 파일의 이전 내용(다리 리깅)은 **폐기됐다.** 아트 방향이 바뀌어 D7 로 옮겨간다.

---

## 0. 도현의 판정

현재는 `gap ≤ engageGap` 이 되면 **무조건** 추월→차단→뒤돌기로 간다. 그게 틀렸다.

- **평소** — 호랑이는 **뒤에서 쫓으며 앞을 본 채 앞발로 후려친다.** 추월도 뒤돌기도 없다
- **플레이어가 뒤로 갔을 때만** — 추월 → 앞을 막음 → 뒤돌기 → 정면 공격

## 1. 이 변경이 왜 옳은가 (구현 전에 읽어라)

`A` 는 실제로 후진하는 게 아니라 **느려지는 것**이다 (`speedBack: 120`, 호랑이 `chaseSpeed: 245`).
⇒ **추월은 억지 트리거가 필요 없다. 느려지면 호랑이가 따라잡아 지나친다 — 물리적으로 저절로 일어난다.**
`chase` 에서 `gap ≤ engageGap` 일 때 `overtake` 로 강제 전이시키는 **그 한 줄이 문제의 전부**다.

그리고 이 변경은 전략층을 만든다. `tigerVulnerable()` 은 `overtake`(×1.5)와 `recover`(×2) 구간이다.
추월이 후퇴할 때만 일어나므로 → **일부러 물러나 추월당하고 큰 피해를 꽂는** 고위험 선택지가 생긴다.
`HANDOFF.md` 의 "유일한 자원은 거리"와 정확히 맞물린다. 이 성질을 죽이지 마라.

## 2. 새 상태 흐름

```
                 gap > 0 (호랑이가 뒤)                 gap < 0 (호랑이가 앞)
                 ────────────────────                 ────────────────────
  chase ──gap≤engageGap──▶ rearWindup                 overtake ──▶ brace ──▶ windup
                             │                                                │
                             ▼                                                ▼
                          swing ──▶ recover ──▶ cooldown ◀───────────────── swing
                             ▲                      │
                             └──── gap 안쪽이면 ─────┘   (멀면 chase 복귀)

  chase 중 호랑이가 플레이어를 따라잡아 gap ≤ 0 이 되면 ──▶ overtake (밀치고 지나간다)
```

### 2-a. 후방 교전 (평소) — 새 경로
- `chase` 에서 `gap > 0 && gap ≤ engageGap` → **바로 windup**. `overtake` 를 거치지 않는다
- 호랑이는 **앞을 본 채**다. `render.js` 의 `drawTiger` 는 이미 `gap >= 0` 이면 `face = 1` 이라
  뒤돌지 않는다 — 다만 지금은 `attacking` 상태를 `chase|overtake` 에서 제외하는 분기가 있으니
  후방 교전에서도 앞발(`drawTigerClaw`)이 **플레이어 쪽(오른쪽)으로** 뻗는지 확인하라
- 텔레그래프(`drawTelegraph`)가 뒤쪽 호랑이 위에서도 제대로 보이는지 확인하라
- **자세 거울 규칙 유지**: windup 진입 시점 자세를 노린다. 서 있으면 상단, 수그리면 하단
- **windup 중 접근 유지**: 지금의 `Math.sign(gap) * approachSpeed` 가 그대로 맞다.
  뒤에 있으면 +방향으로 다가온다 → 시각적 위협이 커진다

### 2-b. 전방 교전 (후퇴 시) — 기존 경로 유지
`overtake → brace → windup → swing → recover → cooldown` 는 **그대로 둔다.** 잘 돌고 있다.
진입 조건만 바꾼다: **강제 전이를 없애고, 호랑이가 실제로 플레이어를 따라잡았을 때만** 들어간다.

### 2-c. 추월 진입 조건 — 위치가 정한다, 플래그가 아니라
`chase` 또는 후방 교전 중 호랑이가 플레이어에게 바짝 붙으면(`gap` 이 `bodyGap` 아래로) → `overtake`.
**입력 비트(`INPUT_KEY.A`)를 읽어서 판단하지 마라.** 장애물에 걸려 느려진 경우도 똑같이
추월당해야 자연스럽다. 위치만 보면 둘 다 공짜로 처리된다.

### 2-d. 밀치고 지나가기
호랑이가 플레이어를 지나칠 때 그냥 통과하면 허전하다. `overtake` 진입 순간 한 번:
- `S.player.stumble = CFG.player.stumbleTime` + `S.events.push({ kind: 'stumble' })`
- **HP 는 깎지 마라.** HP 손실은 발톱만의 몫이다 (이중 처벌 금지)
- 순간이동 금지 — 위치는 속도 적분으로만 바뀐다

## 3. 지켜야 할 불변식 (D3·D4 에서 어렵게 얻은 것들이다 — 깨면 회귀다)

1. **무입력 플레이어는 결국 죽는다.** 지금은 장애물 → 비틀거림 → 호랑이 접근 → 교전 경로로 40.2초에 죽는다.
   후방 교전으로 바뀌어도 이 경로가 살아 있어야 한다. **헤드리스 60초 무입력으로 실제 측정하라**
2. **`A` 홀드 60초에 `|gap| ≤ gapMax`(620).** 이탈 불가 클램프 두 줄을 지워선 안 된다
3. **순간이동 금지.** 프레임당 최대 이동이 `overtakeSpeed/60 = 7.2px` 를 넘지 않아야 한다
4. **텔레그래프 0.5초 + 자세 거울 규칙**
5. **결정론 3/3.** `tiger.js`·`player.js`·`config.js` 는 스캔 대상이다 —
   `Math.sin/cos/pow/atan2` 와 `**` 금지, `Math.sign`·`abs`·`min`·`max`·`sqrt` 는 허용

## 4. 튜닝값은 전부 `config.js` 로

새로 필요한 값(추월 진입 거리, 밀치기 세기 등)은 `CFG.tiger` 에 이름을 주고 넣어라.
다른 파일에 숫자를 하드코딩하지 마라.

`engageGap`(175) 은 이제 **후방 교전 진입 거리**다. 후방에서 앞발이 닿는 거리가 맞는지
`reach`(195) 와 함께 검토하고, 필요하면 값을 바꾸되 **왜 바꿨는지 로그에 적어라.**

## 5. 검증 — 헤드리스로 실제 측정하라 (D4·D5 에서 쓴 Edge CDP)

1. `node --test tests/determinism.test.mjs` 3/3
2. `node build.mjs` 성공
3. **무입력 60초**: 죽는가? 몇 초에? (D4 기준 40.2초) — 안 죽으면 실패다
4. **D 홀드 60초**: 계속 도망칠 때 `|gap|` 최대값. 클램프 620 안인가
5. **A 홀드 60초**: 추월이 일어나는가, 몇 초에? `|gap|` 최대값 620 안인가.
   추월 → brace → 정면 공격까지 전 상태 전이가 도는가
6. **무입력 60초 중 상태 히스토그램**: `overtake`/`brace` 가 (장애물로 느려질 때 말고는)
   거의 안 나오는지 = 평소엔 후방 교전이라는 증거
7. **프레임당 최대 이동량** 측정 (순간이동 회귀 검사)
8. 실제 캔버스 캡처로 후방 교전 그림 확인: 호랑이가 안 뒤돌았는가, 앞발이 플레이어 쪽인가,
   텔레그래프가 보이는가
