## 1. 후방 공격이 시작만 되고 끝까지 못 간다 — 가장 중요

**계산**: 후방 `windup` 중 호랑이는 `blockSpeed(250) + approachSpeed(115) = 365` 로 접근한다.
장애물에 걸린 플레이어는 `speedBase(250) × stumbleMul(0.35) = 87.5`.
초당 **277px** 좁혀지므로 `engageGap(175)` → `bodyGap(95)` 까지 **0.29초**.
그런데 `windup` 은 **0.5초**다. ⇒ **후려치기 전에 접촉 판정이 먼저 걸려 `startOvertake()` 로 중단된다.**

### 고칠 방향 — 후방 교전 중에는 호랑이가 스스로 붙지 않는다
후방 교전 상태(`windup`/`swing`/`recover`/`cooldown` 이면서 `gap > 0`)에서는
**호랑이 위치를 `gap >= standoffGap` 으로 클램프**하라. `CFG.tiger.standoffGap` 을 새로 만들고
**115** 정도에서 시작하라 (`reach` 195 안이라 후려치기는 닿는다).

```
후방 교전 상태 && gap > 0 이면:  T.x = Math.min(T.x, S.worldX - K.standoffGap)
```
⚠ 전방 교전(`gap < 0`)에는 이 클램프를 걸지 마라. 기존 `blockGap`/`bodyGap` 흐름 그대로다.
⚠ 클램프는 **속도 적분 뒤의 상한**이지 순간이동이 아니다. `Math.max` 로 뒤로 끌어당기지 마라.

그리고 접촉 기반 `startOvertake()` 는 **`chase` 에서만** 걸리게 하라.
공격 도중에 중단되면 안 된다.

## 2. 그러면 추월은 언제 하나 — "플레이어가 호랑이보다 느린가"

`cooldown` 이 끝나는 시점에 판정한다:

```
if (S.player.speed < T.chaseSpeed)        → startOvertake()   // 못 따라온다 → 지나친다
else if (|gap| > disengageGap)            → chase
else                                       → startWindup()     // 후방에서 한 번 더
```

**`S.player.speed` 는 입력 플래그가 아니라 이미 계산돼 있는 상태값**이다 (`player.js` 가 매 프레임 쓴다).
그래서 이 한 줄이 셋을 동시에 처리한다:
- `A` 홀드(120) → 느리다 → 추월당한다 ✔ 도현이 말한 그대로
- 장애물 비틀거림(87.5) → 느리다 → 추월당한다 ✔ 자연스럽다
- **조준 중(250×0.55=137)** → 느리다 → 추월당한다 ✔ **쏘는 데 거리를 낸다는 HANDOFF 명제와 맞는다**
- 평속(250)·`D`(340) → 안 느리다 → 뒤에서 계속 후려친다 ✔ 이게 "평소"다

## 3. 발톱 넉백 방향 (지금은 안 터졌을 뿐, 후방 공격이 성립하면 바로 터진다)

```js
S.worldX -= CFG.tiger.clawKnockback;   // 항상 뒤로 — 호랑이가 앞에 있을 때만 맞는 식
```
후방에서 맞으면 플레이어가 **호랑이 쪽으로** 밀린다. `gap 115 → -15` 로 부호가 뒤집히고
`blockPlayerBody()` 가 `S.worldX = T.x - bodyGap` 으로 순간이동시킨다. D3 에서 화살 넉백에
똑같은 버그를 고쳤다 — **방향은 `gap` 부호에서 유도한다.**

- **전방 피격**(gap < 0): 지금 그대로. 뒤로 `clawKnockback`(130)
- **후방 피격**(gap > 0): **앞으로** `CFG.tiger.clawKnockbackRear`(새 값, **45** 에서 시작)
  **+ `S.player.stumble = CFG.player.stumbleTime`**

⚠ 후방 넉백에 stumble 을 반드시 같이 줘라. 앞으로 밀리면 **거리를 벌어 점수가 오른다** —
맞았는데 이득이 되면 안 된다. 비틀거림 0.6초가 `(250-87.5)×0.6 = 97.5px` 를 까므로
`+45 - 97.5 = 순손실 52px` 이 된다. 이 부호를 확인하고 값을 맞춰라.

## 4. 앞선 호랑이가 영영 안 돌아온다

`chase` 에서 `gap < 0` 일 때 속도가 `blockSpeed × aheadChaseMul = 175` 고정이다.
`A` 홀드 플레이어(120)는 **영원히 못 따라잡는다** — 호랑이가 `gapMax`(620)에 붙박여 게임이 멈춘다.
(실측: A 홀드 60초에 chase 94%, 무피해)

**앞선 호랑이는 항상 플레이어보다 느려야 한다** — 그래야 플레이어가 다시 추월해 후방 교전으로 돌아온다.
`CFG.tiger.aheadChaseFrac`(예 **0.7**)을 만들고 `S.player.speed * aheadChaseFrac` 를 쓰라.
평속 250 이면 175 로 지금과 같고, A 홀드 120 이면 84 가 되어 플레이어가 되돌아 추월한다.
`aheadChaseMul` 은 제거하거나 상한으로만 남겨라.

## 5. 합격 기준 — `node tools/balance-probe.mjs` 로 판정한다

1. **무입력·D 홀드에서 후방 예고 > 전방 예고.** 평소엔 뒤에서 싸운다는 증거다
2. **A 홀드에서 추월이 반복적으로** 일어나고(1회로 끝나지 않고), 호랑이가 `gapMax` 에 붙박이지 않는다
3. **무입력 사망 시간이 35~60초 범위**에 있다 (D4 40.2초 · D6 49.0초). 안 죽으면 실패
4. **후방 발톱 피격의 `gap` 이 양수**로 기록된다 (probe 의 `발톱 gap` 항목). 부호가 뒤집히면 3번 실패
5. `|gap| ≤ 620` 전 패턴 유지 · 프레임당 최대 이동 ≤ 7.2px (순간이동 검사)
6. 결정론 3/3 · `node build.mjs` 성공

**probe 에 필요한 항목이 없으면 `tools/balance-probe.mjs` 를 확장해도 된다** (이건 검산 도구지 sim 이 아니다).
확장했으면 무엇을 왜 추가했는지 로그에 적어라.

7. 마지막으로 헤드리스 캡처 한 장: 후방 교전 중 호랑이가 **안 뒤돌고** 앞발이 플레이어 쪽으로 뻗는가,
   텔레그래프가 보이는가.
