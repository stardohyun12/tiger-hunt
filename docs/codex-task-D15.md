# Codex 작업 지시 — D15: 고스트 — 자기 최고기록과 나란히 달린다 (서버 0)

**먼저 `AGENTS.md` 를 읽어라.** 이번 작업은 **sim 로직을 바꾸지 않는다.**
sim 을 고쳐야만 되는 상황이 오면 그건 설계가 틀린 것이다 — 멈추고 로그에 적어라.

---

## 0. 왜 이걸 하는가

`docs/design/multiplayer-plan.md` (2026-08-20 도현 승인) 의 **사다리 1단**이다.

> "멀티가 아쉽다"의 원인은 대전이 없어서가 아니라 **화면에 다른 사람의 존재가 없어서**다.
> 매일 같은 시드라 전원이 **같은 판**을 푼다 ⇒ 고스트가 곧 직접 대결이다.

그리고 이건 **이 출품작의 차별점을 화면에 보이게 만드는 유일한 방법**이다.
결정론은 지금 테스트 안에서만 증명돼 있어서 **심사자 눈에 안 보인다.**
고스트가 돌면 "이 게임은 입력열만으로 판을 완벽히 재현한다"가 한눈에 읽힌다.

**서버는 안 만든다.** 이번엔 `localStorage` 하나로 끝나는 범위다.
(랭킹·Cloudflare Workers 는 별도 작업이다. `worker/` 를 건드리지 마라.)

---

## 1. 이미 있는 것 — 새로 만들 게 아니다

| 있는 것 | 어디 |
|---|---|
| 입력 델타 기록 | `replay.js` `record()` — `main.js` 가 매 프레임 이미 부르고 있다 |
| 직렬화 / 역직렬화 | `replay.js` `serialize()` / `deserialize()` — 정수만 담긴다 |
| 통짜 재생 | `replay.js` `playback()` |
| 같은 코스 보장 | `main.js` `dailySeed()` |
| 최고점수 저장 | `main.js` `loadBestScore()` / `saveBestScore()` — **localStorage 배관이 이미 있다** |

**부족한 것은 하나뿐이다: `playback()` 이 통짜로 끝까지 돌아버린다.**
고스트는 본 게임과 **나란히 한 프레임씩** 가야 한다.

---

## 2. `replay.js` 에 커서 재생을 추가한다

기존 `playback()` 을 **고치지 마라.** 테스트 2번과 (나중의) 서버 검증기가 그걸 쓴다.
옆에 커서 API 를 새로 놓아라:

```
createPlayback(replay) -> cursor     // 내부에 자기 S 와 markerIndex 를 가진다
stepPlayback(cursor)   -> boolean    // 한 논리 프레임 진행. 끝났으면 false
```

- `playback()` 을 `createPlayback` + `stepPlayback` 루프로 **다시 구현해서 중복을 없애라.**
  두 경로가 갈리면 고스트와 서버 검증이 서로 다른 답을 낸다 — 이 프로젝트에서 제일 위험한 종류의 버그다
- 커서의 상태는 커서 객체 안에만 둬라. 모듈 지역 상태 금지
- **브라우저 API 를 쓰지 마라.** `replay.js` 는 Workers 에서도 그대로 돌아야 한다

## 3. 저장 — 최고점 런의 입력열

`main.js` 의 `finishRun()` 이 이미 최고점을 판정한다. **거기에 얹어라.**

- 최고점 갱신 시 `serialize(S.replay)` 를 `localStorage` 에 저장. 키에 **시드를 포함**하라
  (`dailySeed()` 가 날마다 바뀐다 — 어제 코스의 고스트를 오늘 띄우면 딴 데서 달린다)
- 불러오기는 **시드가 일치할 때만**. 불일치하면 고스트 없이 그냥 시작한다
- ⚠ **용량 상한을 걸어라.** 조준 좌표가 매 프레임 바뀌면 60초에 100KB 를 넘는다.
  직렬화 결과가 `CFG.ghost.maxBytes`(예: 400_000)를 넘으면 **저장을 건너뛰고 조용히 넘어가라**
- ⚠ `localStorage` 는 차단·용량초과로 **던진다.** `saveBestScore()` 가 하듯 전부 try/catch 로 감싸라.
  저장 실패가 게임을 멈추면 안 된다
- 어제 시드의 낡은 항목은 지워라 (키 접두사로 훑어서 정리). 무한히 쌓이면 언젠가 용량이 찬다

## 4. 병행 재생 — 여기가 함정 구간이다

`main.js` 에서 본 게임 sim 을 한 프레임 돌릴 때마다 고스트 커서도 한 프레임 돌린다.

⚠ **아래 다섯 개를 전부 지켜라. 하나만 틀려도 티가 크게 난다.**

1. **고스트는 완전히 분리된 `S` 다.** 본 게임 `S` 와 어떤 필드도 공유하지 마라
2. **고스트의 `S.events` 를 절대 소비하지 마라.** fx·오디오·hitstop 이 두 배로 터진다.
   `stepPlayback` 이 돌린 상태의 events 는 그냥 버린다
3. **고스트는 본 게임의 hitstop 에 멈추지 않는다.** 고스트는 자기 리플레이의 시간축을 그대로 산다
   (그 리플레이 안에 그때의 hitstop 이 이미 들어 있다). 본 게임이 멈춘 동안 고스트만 흐르는 게 **정답**이다
4. **`phase === 'play'` 일 때만 고스트를 진행시켜라.** 타이틀 데모에서 같이 돌면 안 된다
5. 재시작하면 고스트 커서도 **처음부터 새로 만든다**

## 5. 화면 — 최소한만 그린다

`multiplayer-plan.md` 의 규율 그대로:

- **반투명 사슴 실루엣 + 점수만.** 고스트의 화살·호랑이·과녁·먼지는 **그리지 마라.**
  두 벌이 겹치면 화면이 죽고, 어느 게 내 호랑이인지 못 읽는다
- 화면 x = `playerScreenX + (ghostWorldX - S.worldX)`. 즉 **앞서 있으면 오른쪽에** 보인다
- 화면 밖으로 나가면 **가장자리에 표시**하라 — 방향 표시 + 격차(m). 이게 없으면
  고스트가 사라진 건지 내가 이긴 건지 모른다. **격차 숫자가 이 기능의 절반이다**
- 고스트가 죽은 지점(리플레이가 끝난 지점)에 **작은 표식**을 남겨라 — "여기까지 갔었다".
  이걸 지나치는 순간이 이 기능의 보상이다. 지나칠 때 짧은 피드백을 줘라
- 색은 **민화 4색 안에서.** 주홍은 위험 전용이라 **쓰지 마라.** 흐린 먹 실루엣이 맞다
- 고스트가 없을 때(첫 판·시드 불일치) **아무것도 그리지 마라.** 빈 UI 를 띄우지 마라

## 6. 조준 좌표 양자화 — 용량이 실제로 문제일 때만

측정부터 하라. 60초 런의 직렬화 크기를 찍어봐라. 100KB 를 넘고 마커 대부분이
조준 좌표 1~2px 흔들림이면 그때만 손대라:

- **`input.js` 의 `sampleInput()` 에서 `ax`/`ay` 를 격자에 맞춰라** (예: 2px).
  sim 이 받는 값과 저장되는 값이 **항상 같아야** 하므로, 반드시 입력 생성 단계에서 해야 한다
- ⚠ **`sim` 안에서 양자화하지 마라.** 결정론이 아니라 *기록과 재생의 일치*가 깨진다
- 격자를 키우면 조준이 거칠어진다. 2px(뷰 폭 960 기준 0.2%)를 넘기지 마라
- 하고 나면 결정론 테스트 3/3 을 다시 확인하라

## 7. 검증

1. **결정론 3/3** · `node build.mjs` 성공 · `dist/play.html` 크기 보고
2. **왕복 일치 검증을 하나 추가하라** (`tests/` 에):
   같은 리플레이를 `playback()` 통짜 재생과 `createPlayback`+`stepPlayback` 커서 재생으로 각각 돌려
   **`hashState()` 가 같은지** 확인한다. 두 경로가 갈리는 순간을 이 테스트가 잡는다
3. `node tools/balance-probe.mjs` 가 여전히 통과 (밸런스 판정 유지)
4. 헤드리스 확인: 한 판을 sim 으로 돌려 리플레이를 만들고, 그걸 커서 재생하며
   **매 프레임 `worldX` 가 원본과 정확히 일치하는지** 찍어봐라. 한 프레임이라도 어긋나면 실패다
5. 캡처: 고스트가 앞서 있는 화면 · 화면 밖 격차 표시 · 고스트 사망 표식
   (D11~D12 의 Chrome 단일 프로세스 소프트웨어 렌더 경로. 2분 안에 안 붙으면 포기하고 로그에 적어라)
