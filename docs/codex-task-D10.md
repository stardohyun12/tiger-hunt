## 1. 왜 빌딩으로 보이는가 (원인은 구조다, 값이 아니다)

`drawSteppedLayer` 가 각 블록을 **`baseY` 까지 내려오는 통짜 세로 기둥**으로 그린다:

```js
ctx.fillRect(x + index * blockW, baseY - height, blockW, height);
```

그리고 인접 블록 높이가 `[42, 78, 126, 93, 150, 102, 66, 39]` — 한 칸 건널 때마다 **50px 씩 튄다.**
폭 40px 짜리 기둥이 수직 벽면을 만들며 나란히 선다. **그게 빌딩이다.**

덤으로 **원근이 뒤집혀 있다**: 먼 층(42~150)이 중간 층(18~105)보다 높다.

**산은 기둥이 아니라 능선이다.** 인접 칸의 높이차가 작아야 비탈이 된다.

## 2. 능선으로 다시 만들어라

### 2-a. 봉우리를 정의하고, 열(column) 높이는 계산해서 뽑는다
높이 배열을 손으로 나열하지 마라. **봉우리 목록**을 두고 열마다 높이를 계산하라.

```js
// config
farRidges: [ { x: 0, h: 84, spread: 2600 }, { x: 420, h: 62, spread: 3400 }, ... ]
```

열 높이는 **2차 곡선**으로:
```
h(dx) = peak.h - (dx * dx) / peak.spread        // dx = 열 중심 - peak.x
열 높이 = max(0, 모든 봉우리에 대한 h(dx) 의 최댓값)
```

이 식을 쓰는 이유가 있다. 2차 곡선은 **꼭대기가 완만하고 아래로 갈수록 가팔라진다** —
그게 한국 산의 실루엣이다. 알프스식 뾰족한 삼각형이 아니다.
`spread` 가 클수록 넓고 완만한 산이 된다.
봉우리가 겹치면 `max` 가 알아서 하나의 능선으로 합친다 — **겹치는 능선이 산수화의 핵심**이다.

⚠ `config.js` 는 결정론 스캔 대상이라 **숫자만** 넣어라. 계산은 `render.js` 에서 한다
(`render.js` 는 스캔 대상이 아니라 `Math.*` 자유).

### 2-b. 칸을 잘게
`blockW: 40` → **`A.px * 2`(6뷰단위)** 정도로 줄여라. 그래야 계단이 비탈로 읽힌다.
너무 잘게 하면(px 1칸) 계단감이 사라져 이 양식이 죽는다 — 2칸이 적당하다.
**인접 열의 높이차가 3칸(9뷰단위)을 넘지 않는지** 검증하라. 넘으면 벽면이 생긴다.

### 2-c. 원근을 바로잡아라
- **먼 층(`inkFar`)**: 낮고 넓고 완만하다. 느리게 스크롤(0.12 유지). 여러 봉우리가 길게 겹친다
- **중간 층(`inkMid`)**: 앞에서 겹치며 능선이 더 또렷하다. 빠르게 스크롤(0.28 유지)
- 두 층의 능선이 **서로 겹쳐 보여야** 깊이가 산다. `baseY` 를 조정해 중간 층이 먼 층의
  아랫부분을 가리게 하라
- **먹 알파는 계속 두 단계만** (`C.inkFar` · `C.inkMid`). 세 번째 회색을 만들지 마라

### 2-d. 운무 (해보고 어색하면 빼라)
먼 능선 위로 **한지색 가로 띠 1~2개**를 얇게 깔면 안개에 잠긴 산이 된다.
산수화의 문법이고, 층 분리도 같이 해결된다. 새 색이 아니라 배경색이라 팔레트 규율도 안 깨진다.
**어색하면 넣지 마라** — 판단은 캡처를 보고 하라.

### 2-e. 구름
지금 구름(`drawClouds`)은 3단 rect 라 괜찮다. 유지하되, 산과 높이가 겹쳐 지저분하면
더 위로 올려라.
