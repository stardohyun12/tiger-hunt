# D1 — 2026-08-19 · 리포 뼈대, 규약, 프로토타입 편입

## 사람이 정한 것 (이날의 결정)

1. **엔진: 순수 JS + Canvas2D. LÖVE(Lua) + love.js 는 검토 후 기각.**
   - 브라우저가 UDP를 못 써 LÖVE 의 `enet` 이 love.js 에서 죽는다. WebSocket 은 Emscripten JS 글루를 직접 짜야 붙는다
   - sim 을 Cloudflare Worker 에서 그대로 못 돌려 **서버측 스코어 검증이 무너진다**
   - "에디터가 AI 에이전트에게 병목"이라는 명제는 LÖVE 가 아니라 *에디터 없음*을 지지한다

2. **Vite·TypeScript 도 기각.** 프로토타입의 무의존성 `build.mjs` 가 이미 **22KB 단일 파일**(`dist/play.html`)을 낸다. 빌드 도구를 얹을 이유가 없다.

3. **결정론을 float 를 유지한 채로 얻기로 했다.** ← *이날 오전의 "정수 고정소수점 ×1000" 결정을 뒤집은 것*
   프로토타입 sim 의 Math 사용을 전수 조사한 결과 `min×5 max×3 abs×1 hypot×1 random×5` 뿐이고 **초월함수가 하나도 없었다.**
   IEEE 754 기본 연산(`+ - * /`, `sqrt`)은 표준이 결과를 정확히 규정하고, Chrome·Node·Workers 는 전부 V8 이다.
   ⇒ 물리를 갈아엎는 대신 **초월함수 금지 · 고정 timestep 1/60 · seeded PRNG · 입력 정수 양자화** 넷만 강제한다.
   근거: 고정소수점 전환은 물리 전체를 다시 쓰게 만들어 D2~D3 을 통째로 먹는다. 얻는 것에 비해 값이 비싸다.

4. **실시간 멀티는 lockstep 이 아니라 위치 브로드캐스트.**
   각자 자기 호랑이와 싸우는 게임이라 입력을 동기화할 이유가 없다. 같은 시드 트랙 + 상대 위치 전송이면 충분하고 float 여도 안전하다.
   **방해 수단은 기존 규칙에서 나온다** — 호랑이를 세게 맞히면 상대 트랙에 장애물이 생긴다. 거리를 뺏는 게임이니 상대의 거리를 뺏는 것으로 확장.

5. **모바일 지원한다 — 화면 버튼 방식.** D6 에 붙인다.

6. **에셋은 전부 새로 만든다.** 다른 리포에서 재활용하지 않는다 — 아트 방향이 이전 프로젝트에 끌려가지 않게.
   SFX 는 음원 파일 없이 **WebAudio 코드 합성**.

7. **게임: 《호랑이 추격》.** claude.ai 웹에서 만든 프로토타입(725줄)을 본체로 채택.
   방침은 **"일단 만들어보고 고친다"** — 규칙을 확정 취급하지 않되 `HANDOFF.md` 의 "손대지 말아야 할 것"은 지킨다.

## 발견한 문제 (D2 로 넘김)

프로토타입의 **의존 방향이 어긋나 있다**:
- `arrow.js` 가 `input.js` 의 `mouse` 를 직접 읽는다
- `arrow.js` 에 `drawAimPreview`(렌더)가 들어 있다
- `tiger.js` · `obstacle.js` 가 `fx.js` 의 `triggerFx` 를 호출한다 (sim → presentation 역방향)

이것 때문에 `src/` 를 `sim/`·`render/` 로 나누려던 걸 되돌리고 평평하게 뒀다. 계약을 위반하는 파일을 계약 폴더에 넣는 건 거꾸로다. **분리는 결정론화와 같은 파일을 건드리므로 D2 에 한 번에 한다.**
