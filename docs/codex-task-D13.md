도현(2026-08-21, `dist/play.html` 플레이 후):

1. **"앞뒤로 갈 때 속도감이 안 느껴짐. 기본 이동에서도 속도감이 조금 있어야 하는데 없음"**
2. **"화살을 계속 쏘니까 리스크도 없고, 가까이 오면 계속 연타하면 됨"**
3. **"컴퓨터는 앞뒤 AD · 점프 Space · 숙이기 S 가 조작감이 덜 불편함"**
4. **"계속 A를 눌러 뒤로 가면 호랑이를 지나쳐 뒤로 가는데, 그때 호랑이한테 막혀서 끊남"**

②와 ④는 감각 문제가 아니라 **실제로 깨져 있다.** 헤드리스로 확인했다.

### ② 지금 최적 전략은 "가만히 서서 클릭 연타"다

| 전략 | 결과 |
|---|---|
| 과녁 봇 (D12 합격 기준) | 60초 **8,575점** |
| **탭 연사 봇** (2프레임 주기 클릭, 이동 입력 없음) | 120초 **무피해 생존 · 11킬 · 19,575점** |
| 탭 연사 봇 (12프레임 주기) | 120초 **무피해 생존 · 8킬 · 13,815점** |

원인은 둘이다:
- 차지 0에서 놓아도 `dmgMin: 9` 짜리 화살이 나간다
- `S.aiming` 은 **홀드하는 동안에만** 켜진다 → **탭 발사는 감속 페널티가 정확히 0**

즉 대가 없이 DPS가 무한히 쌓인다. **D12 에서 세운 "과녁 > 도망" 역전이 연사 봇에게 다시 깨져 있고,
`balance-probe` 에 연사 봇이 없어서 못 잡았다.**

### ④ A만 누르면 사실상 무적이고, 호랑이는 사거리 밖에서 헛스윙한다

A 홀드 120초 로그 (시드 12345):

```
23.3s  hp 3 → 2   (첫 타)
...
37.5s  brace → windup   gap = -291
38.0s  windup → swing   gap = -299   ← reach 195 밖. 절대 안 맞는 스윙
39.3s  cooldown → chase gap = -473
53.7s  chase → overtake            ← 14초간 아무 일도 없음
(이 17초 루프가 120초 내내 반복. hp 2로 끝까지 생존)
```

원인은 `src/tiger.js` 의 교전 이동식이다:

```js
const approach = T.state === 'windup' ? Math.sign(gapOf(S)) * K.approachSpeed : 0;
T.x += (K.blockSpeed + approach) * FIXED_DT;
```

`blockSpeed`(250)가 **고정 상수라서 항상 +x(앞) 방향**이다. 플레이어가 A로 120까지 느려져도
호랑이는 250-115 = **+135로 계속 앞으로 달린다.** 앞을 막는다면서 **플레이어 반대편으로 도망가는 것**이다.
`brace → windup` 전환도 `turnTime` 만 보고 일어나 **거리 확인이 없다.**

## 1. 활에 대가를 붙인다 (②) — 새 자원은 만들지 마라

⚠ `HANDOFF.md`: **"이 게임의 유일한 자원은 거리다. 체력바를 추가하거나 다른 자원을 늘리는 방향은 피할 것."**
**화살 개수·전통(quiver)·탄약 UI 를 만들지 마라.** 대가는 전부 **거리**로 받는다.

`CFG.aim` 에 두 값을 추가한다:

| 값 | 제안 시작값 | 뜻 |
|---|---|---|
| `minCharge` | `0.25` (초) | 이보다 짧게 놓으면 **화살이 나가지 않는다.** 시위를 못 먹인 것 |
| `nockTime` | `0.45` (초) | 발사 직후 이 시간 동안 **새 차지를 시작할 수 없다** |
| `nockMul` | `0.75` | 재장전 중 속도 배율 (`aimMul: 0.55` 와 같은 계열로 곱연산) |

규칙:
- `minCharge` 미만에서 놓으면 **발사 실패 + 차지 취소**. 이때는 `nockTime` 을 **소모하지 않는다**
  (실수 클릭이 벌이 되면 안 된다). 실패했음을 알 수 있는 짧은 표시만 준다
- 발사에 성공하면 `S.nock = CFG.aim.nockTime`. 그동안 `startCharge()` 가 무시되고,
  `updatePlayer()` 의 속도 배율에 `nockMul` 이 곱해진다
- **결과적으로 "쏘는 동안 계속 느리다."** 조준 0.25초 + 재장전 0.45초 = **최소 0.7초는 감속 상태**다.
  이게 리스크다. 연타로 이 창을 피할 수 없어야 한다

`S.nock` 은 반드시 `state.js` 의 `createState` 에 넣고 `FIXED_DT` 로 깎아라. 모듈 지역 상태 금지.

### 합격 기준
`tools/balance-probe.mjs` 에 **연사 봇**을 추가하라 (위 표를 재현하는 것: 이동 입력 없이 최단 주기로
차지-릴리스를 반복하며 호랑이를 조준). 판정:

- **연사 봇 점수 < 과녁 봇 점수** — 이게 핵심
- **연사 봇은 60초 무피해 생존을 못 해야 한다** (지금은 120초 무피해다)
- 과녁 봇은 여전히 D 홀드보다 높아야 한다 (D12 판정 유지)

세 줄을 나란히 찍어라. 과녁 봇이 `nockTime` 때문에 D 홀드 아래로 떨어지면
`nockTime`·`dashTime`·`dashSpeed` 를 조정해서 **다시 역전시켜라.** 명중은 여전히 이득이어야 한다.

## 2. 앞막기를 고친다 (④)

**핵심 수정: 교전 중 호랑이의 기준 속도를 고정 상수가 아니라 `S.player.speed` 로 바꾼다.**

호랑이가 앞을 막는다는 건 "플레이어와 나란히 달리며 거리를 좁힌다"는 뜻이다. 기준이 절대속도면
플레이어가 감속했을 때 저절로 멀어진다. 기준을 플레이어 속도로 두면 `approachSpeed` 항이
**순수하게 '붙는 양'** 이 된다:

```js
// 교전(windup/swing/recover/cooldown) 중
const toward = -Math.sign(gapOf(S)) * K.approachSpeed;  // 부호 주의: 플레이어 쪽으로
T.x += (S.player.speed + toward) * FIXED_DT;
```

⚠ **부호를 직접 검산하라.** `gapOf(S) < 0`(호랑이가 앞)이면 호랑이는 **뒤(-x)로** 와야 붙는다.
지금 코드는 정확히 그 반대다. 고친 뒤 A 홀드 로그에서 `windup → swing` 시점의 `|gap|` 을 찍어
**사거리(`reach: 195`) 안인지 눈으로 확인하고 지나가라.**

추가로:
- **`brace → windup` 에 거리 조건**을 넣어라. `|gap| > engageGap` 이면 windup 으로 들어가지 말고
  `chase` 로 돌아가라. 사거리 밖에서 예고를 띄우면 신호가 거짓말이 된다
- 후방 교전(gap>0)의 `standoffGap` 클램프는 **그대로 둬라** — D7~D12 에서 조정된 값이다
- `blockPlayerBody()` 가 매 프레임 `stumble` 을 다시 세팅해 **영구 비틀거림**이 되지 않는지 확인하라.
  접촉이 유지되는 동안은 한 번만 걸려야 한다

### 합격 기준
`balance-probe` 에 **A 홀드 봇**을 추가하라. 판정:

- **A 홀드 봇이 30~60초 안에 죽어야 한다** (지금은 120초 hp2 생존)
- `windup → swing` 전환의 **90% 이상**에서 `|gap| ≤ CFG.tiger.reach` 여야 한다 (헛스윙 비율을 찍어라)
- D 홀드·무입력·과녁 봇의 기존 판정이 깨지지 않았는지 같이 확인하라
  (⚠ 이 수정은 D 홀드도 어렵게 만든다. 무입력 사망이 30초 밑으로 떨어지면 과한 것이다)

## 3. 속도감 (①) — **렌더 전용이다**

⚠ **`CFG.view.playerScreenX` 를 건드리지 마라.** `arrow.js` 의 `bowScreen()` 이 이걸로 화살 원점을
계산한다. 렌더에서 플레이어를 다른 x에 그리면 **조준이 어긋난다.** 플레이어 그리기 오프셋을 쓸 거면
**±8px 이내**로 제한하라.

속도감은 "플레이어가 빨라지는 것"이 아니라 **"세상이 빨리 지나가는 것"** 으로 만든다.
`S.player.speed` 를 읽어 `speedBase`(250) 대비 비율을 구하고 아래를 그 비율에 물려라:

1. **근경(foreground) 레이어 추가** — 지금 시차는 `farRidges`/`midRidges` 둘뿐이라 A(120)·기본(250)·D(340)의
   차이가 배경 하나로만 나온다. 지면 근처를 **speed 1.4~1.8 배로 스쳐가는** 풀/돌/흙 조각을 넣어라.
   가까운 것이 빨리 지나가야 속도가 읽힌다. **이게 이 항목에서 제일 큰 몫이다**
2. **속도선** — `speed > speedBase` 일 때 화면 가장자리에 짧은 수평 획. 개수·길이를 초과분에 비례.
   감속(A) 중에는 반대로 **성기고 짧게**. 민화 4색 규율 유지 (주홍은 위험 전용이므로 **쓰지 마라**)
3. **먼지** — `drawDust()` 의 발생 빈도·길이를 속도에 비례시켜라. 지금은 사실상 고정이다
4. **지면 마커** — `groundMarkStep` 을 촘촘하게. 흐름이 읽히는 최소 밀도까지
5. **자세** — 가속 중엔 기수가 앞으로, 감속 중엔 뒤로 (스프라이트 y/x 오프셋 1~2px 수준이면 충분)

**감속(A)에도 반드시 신호를 줘라.** 도현이 지적한 건 "빨라짐"이 아니라 **"앞뒤로 갈 때"** 다.
A를 눌렀을 때 세상이 눈에 띄게 느려져야 "내가 지금 호랑이에게 붙고 있다"가 읽힌다.

## 4. 키 배치 (③)

| 키 | 동작 |
|---|---|
| `Space` / `W` / `↑` | 점프 |
| `S` / `↓` | 수그리기 |
| `A` / `←` | 뒤로 |
| `D` / `→` | 앞으로 |
| `Space` / `Enter` / 좌클릭 | **`title`·`over` 에서만** 시작 / 재시작 |

- `phase` 로 갈라라. `play` 중의 `Space` 는 **점프이지 재시작이 아니다**
- ⚠ **재시작 직후 잔류 입력을 막아라.** `over` 에서 Space 를 누른 채 재시작되면 그 홀드가
  점프로 새면 안 된다. 재시작 시 키 집합을 비우고, 다시 눌러야 점프가 되게 하라
- ⚠ 이동키로는 재시작되지 않는다는 기존 규칙(`HANDOFF.md` 검증 항목)은 **유지**
- 방향키를 새로 받으면 `preventDefault` 목록에 추가하라 (페이지 스크롤 방지)
- **화면의 조작법 표기를 전부 갱신하라** — 타이틀 오버레이·HUD·게임오버.
  조작법 상시 표시는 **대회 필수 요건**이다. 빠뜨리면 실격이다
- 터치 패드(D11 배치)는 **건드리지 마라.** 이건 키보드 얘기다
