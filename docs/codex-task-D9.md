## 1. `tigerWindup` 이 덩어리로 보인다 — 여백이 없어서다

**같은 파일 안에 정답이 있다. `tigerRunA` 는 잘 읽힌다.** 왜 읽히는지 세어보라:

- 목이 잘록하다 — 머리(0~5행 오른쪽)와 몸통 사이에 **폭이 좁아지는 구간**이 있다
- 꼬리가 가늘다 — 왼쪽으로 1~3칸 두께의 사선
- **다리 4개가 빈칸으로 갈라져 있다**: `....XXXX..XXXX........XXXX..XXXX........`
- 채움 비율이 **절반쯤**이다

`tigerWindup` 은 반대다:
- 0~9행이 통짜 쐐기다. **머리와 치켜든 앞발이 한 덩어리로 붙어 있다**
- 다리가 2개뿐이고(`XXXXXX......XXXXXX`) 그마저 굵은 뭉치다
- 채움이 **85% 쯤**이다 ⇒ 실루엣이 아니라 얼룩이다

### 다시 그릴 때 지킬 것 (측정 가능한 기준이다)

`tigerWindup` 과 **`tigerSwing`** 을 다시 그려라.
(swing 을 같이 고치는 이유: windup → swing 이 한 동작으로 읽혀야 한다. 하나만 바꾸면 짝이 깨진다.)

1. **채움 비율 ≤ 55%** — `tigerRunA` 를 실측해서 그 근처로 맞춰라
2. **다리는 4개, 사이 빈칸 2칸 이상.** windup 은 웅크린 자세이므로 뒷다리를 접어 낮추되 갈라져 보여야 한다
3. **목 잘록함**이 있을 것. 머리가 몸통에 먹히면 안 된다
4. **치켜든 앞발이 몸통과 명확히 분리**될 것 — 빈칸 1칸 이상이거나 각도로 확실히 갈릴 것.
   이게 "곧 후려친다"를 말하는 유일한 형태다
5. **먹 줄무늬(`o`)를 몸통에 유지**하라. 호랑이 정체성이다
6. 꼬리를 세워라 — 웅크린 몸 + 곧추선 꼬리가 포식자의 예비동작이다

### 크기와 판정 상자
`tigerRunA/B` 는 40×25 이고 이게 `CFG.tiger.w 120 × h 74` 판정 상자에 대응한다.
**몸통은 반드시 같은 25행 안에 있어야 한다** — 화살 명중 판정(`arrow.js` 의 `inY`)이
`groundY - h` ~ `groundY` 라서, 몸통이 이 밖으로 나가면 **맞췄는데 안 맞는다.**
**치켜든 앞발만 예외로 위로 최대 4행까지** 넘어가도 된다 (사람은 발을 몸통으로 안 읽는다).
스프라이트 행 수가 달라지면 `blit` 이 **바닥 기준으로 정렬**하는지 확인하라.

### 판정판에 채움 비율을 찍어라
`docs/art/sprite-preview.html` 의 각 칸에 **채움 비율 %** 를 표시하라.
그리고 `tigerRunA` · `tigerWindup` · `tigerSwing` 을 **한 줄에 나란히** 놓는 비교 칸을 만들어라.
눈으로 세지 않고 숫자로 판정할 수 있어야 한다.

## 2. 텔레그래프 — 지금은 경고가 아니라 판때기다

현재 `drawTelegraph`:
```js
if (T.state === 'windup' && Math.floor(S.frame / A.telegraph.blinkFrames) % 2) return;
```
`blinkFrames: 2` ⇒ **초당 15번 통째로 사라진다.** 절반의 시간엔 경고가 아예 없다.
그리고 **0.5초가 얼마나 남았는지 알 방법이 없다.** 켜졌다 꺼지는 납작한 사각형 하나가 전부다.

### 2-a. 남은 시간을 눈에 보이게 — 이게 가장 큰 개선이다
`T.timer` 가 `CFG.tiger.windup`(0.50) 에서 0 으로 줄어든다. 진행도
`p = 1 - T.timer / CFG.tiger.windup` 로 띠를 **호랑이 쪽에서 플레이어 쪽으로 채워라.**

- **칸 단위로 채운다** (예 8칸). 부드러운 보간 금지 — 이 양식이 아니다
- 띠가 **플레이어에 닿는 순간이 후려치는 순간**이다. 그래서 타이밍이 몸으로 읽힌다
- 아직 안 채워진 칸은 주홍 **테두리만** (속은 비운다). 채워진 칸은 주홍 꽉 채움
- 통째 점멸(`blinkFrames` 전면 on/off)을 **없애라.** 대신 마지막 20% 구간에서만
  2프레임 단위로 채워진 부분을 깜빡여 급박함을 준다

### 2-b. 상단/하단이 한눈에 갈려야 한다
지금은 `highY 276 · highH 108` / `lowY 366 · lowH 54` 로 위치만 다르다.
**형태로도 갈라라**:
- **상단**(서 있으면 맞는다 → 수그려야 한다): 띠의 **위쪽 가장자리**에 두꺼운 주홍 캡 바
- **하단**(수그리면 맞는다 → 떠야 한다): 띠의 **아래쪽 가장자리**에 두꺼운 주홍 캡 바
- 캡 바가 "이쪽에서 온다"를 말한다

### 2-c. 플레이어 몸에도 표시하라 — 눈이 거기 있다
위협받는 높이에 맞춰 **사슴 위에 작은 주홍 표식**을 겹쳐라 (상단이면 기수/등 높이, 하단이면 다리 높이).
플레이어의 시선은 자기 캐릭터에 있다. 호랑이 쪽만 표시하면 놓친다.
⚠ 사슴 실루엣을 덮어버리면 안 된다 — 작은 표식이지 채우기가 아니다.

### 2-d. `swing` 순간
띠가 다 찬 뒤 `swing`(0.16초) 동안은 **띠 전체를 꽉 찬 주홍**으로. 임팩트다.

### 2-e. 전방/후방 양쪽에서 동작할 것
`direction = gap >= 0 ? 1 : -1` 로 이미 좌우를 가른다. **후방 교전(호랑이가 왼쪽)에서도**
채워지는 방향이 호랑이→플레이어여야 한다. 반대로 채워지면 의미가 뒤집힌다. 둘 다 캡처로 확인하라.

수치는 전부 `CFG.art.telegraph` 에 이름 붙여 넣어라.
